# TimeMachine sustainability plan

[한국어](sustainability-ko.md) · English

The recommended model is a free MIT-licensed core plugin, optional donations, and paid operational support. Backup, verification, and offline restore should remain available without payment.

## Stage 1: public release and donations

- Publish the same free JAR on GitHub and Modrinth.
- Add a donation link only after a controlled account exists.
- Do not add advertising, tracking, or donation prompts to the plugin.
- Keep donor benefits outside backup safety and recovery access.

Choose donation tiers and amounts only after reviewing payment fees, tax handling, and the effort required to maintain each benefit.

## Stage 2: paid operational support

Offer scoped services only when there is repeated demand:

- migration and configuration support
- restore drills in a staging environment
- capacity, FULL schedule, and retention planning
- snapshot diagnosis after an incident
- organization support and compatibility checks

Define access, data handling, response time, deliverables, and liability in writing before work begins. These services are not a software warranty.

## Stage 3: separate optional products

Consider remote storage integration, central monitoring, or audit reports only after demand is proven. Keep the snapshot format and offline recovery path open so operators are not locked into a service.

## Decisions before monetization

1. Confirm the legal owner and public name of the payment account.
2. Review refunds, taxes, privacy, and support scope.
3. Define the code and license boundary for any paid component.
4. Do not change the existing LICENSE owner or contribution record without evidence.

No payment or donation link is included in this repository yet.
