# TimeMachine 지속 가능성 계획

한국어 · [English](sustainability.md)

TimeMachine의 권장 운영 모델은 **MIT 핵심 플러그인 무료 공개 + 자발적 후원 + 선택형 유료 운영 지원**입니다. 백업, 검증, 복원 export와 같은 안전 핵심 기능은 유료 장벽 뒤로 옮기지 않습니다.

## 1단계: 공개 배포와 후원 기반

- GitHub와 Modrinth에는 동일한 무료 JAR을 배포합니다.
- 실제로 관리 가능한 후원 계정을 만든 뒤에만 프로젝트 페이지와 `.github/FUNDING.yml`에 링크를 추가합니다.
- 플러그인에는 광고, 원격 추적, 후원 알림을 넣지 않습니다. 수요 판단은 다운로드, 별, 이슈와 같은 공개 지표로 충분합니다.
- 후원 혜택은 감사 표기, 개발 소식, 기능 우선순위 설문처럼 제품 안전성을 나누지 않는 범위로 제한합니다.

권장 후원 단계의 예시는 개인 후원자, 서버 운영자, 조직 후원자 세 단계입니다. 금액과 결제 수단은 실제 계정의 수수료·세무 처리·지속 가능성을 확인한 뒤 정합니다.

## 2단계: 선택형 유료 서비스

사용자가 반복해서 요청할 때 다음 서비스를 별도 견적으로 제공합니다.

- 기존 백업 체계에서 TimeMachine으로 이전하는 설정 지원
- 스테이징 서버에서 복원 훈련과 결과 보고서 제공
- 저장소 용량, FULL 주기와 retention 정책 설계
- 장애 후 snapshot 진단과 복구 절차 자문
- 조직용 우선 지원과 호환성 검증

서비스는 소프트웨어 보증이 아니라 작업 범위와 결과물을 명시한 지원 계약으로 운영합니다. 운영 서버 접근, 데이터 보관, 응답 시간과 책임 범위는 작업 전에 서면으로 합의해야 합니다.

## 3단계: 수요가 검증된 선택 기능

무료 핵심 플러그인과 분리할 가치가 확인된 경우에만 원격 저장소 연동, 중앙 상태 모니터링, 조직용 감사 리포트 같은 별도 제품을 검토합니다. 공개 포맷과 오프라인 복원 경로는 유지해 사용자가 특정 서비스에 종속되지 않도록 합니다.

## 출시 전 결정 사항

1. 후원 계정의 실제 소유·정산 주체와 공개 명칭을 확정합니다.
2. 후원과 유료 지원에 적용할 환불, 세금계산, 개인정보 및 지원 범위를 검토합니다.
3. 유료 구성요소를 만들 경우 MIT 저장소와의 코드·라이선스 경계를 명시합니다.
4. 기존 `LICENSE`의 법적 권리자와 기여 기록은 별도 근거 없이 변경하지 않습니다.

현재 저장소에는 결제 링크나 가상의 후원 계정을 넣지 않았습니다. 먼저 무료 공개판의 설치·복원 경험과 지원 요청 유형을 관찰한 뒤 1단계부터 시작하는 것이 가장 낮은 위험의 선택입니다.
